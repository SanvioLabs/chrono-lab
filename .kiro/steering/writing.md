# Writing

Applies to every file you write here: specs, docs, code comments, commit
messages and UI copy.

- **No em dashes.** Not in a heading, a sentence or a comment. Use a colon,
  a comma, parentheses, or two sentences. En dashes in number and date ranges
  are fine
- **Use the words in `product.md`** exactly: run, step, timeline, branch, fork
  point, future, replay. Don't invent synonyms
- **Plain and short.** Lead with what something does. Skip "robust",
  "seamless", "leverage" and the like
- **Say what's true now.** A spec states what will be built; a doc states what
  has been built. Don't describe something as done before it is
