# How we used Kiro

A dated line each time a Kiro feature does real work on Chrono-Lab. This becomes
the write-up for the submission, so note what happened, including what didn't
work.

| Date | Feature | What it did | What we learned |
|---|---|---|---|
| 2026-11-03 | (before Kiro) | The starter kit's steering files and spec prompts were drafted in Claude Code as planning. No application code came from it | Planning happened outside Kiro; everything from spec 01 on is Kiro |
| 2026-11-03 | Kiro CLI, spec mode (`kiro-cli chat --v3 --mode spec --no-interactive`), started from Claude Code | Wrote spec 01's requirements, design and tasks from `kiro-prompts/01-trace-and-replay.md`, with read and write tools only | A headless spec run works, but folder creation needs a write tool, not a shell tool. It ignored "property tests first" and used em dashes |
| 2026-11-03 | Steering | Added `.kiro/steering/writing.md` (no em dashes, product vocabulary) after the first spec run | A style rule belongs in steering, not in each prompt |
| 2026-11-03 | Kiro CLI, spec mode, second pass | Revised spec 01 against a nine-point review: replay reuses recorded ids, the network guard covers `fetch` and sockets, the hex scrub pattern is gone, replay takes a stop-at-step boundary for spec 02, tests come before code | Kiro took a written review and fixed all nine points in one run. The spec review caught real bugs before any code existed |
| 2026-11-04 | Kiro CLI (`--v3`), build session, started from Claude Code | Wrote all spec 01 source and tests (`src/trace/`, `src/recorder/`, `src/replay/`, `tests/`) from tasks.md in one session | The shell tool wasn't trusted (`--trust-tools` named `shell`, which this version didn't accept), so no command ran. Tests were written before code in file order, but never seen failing. Claude Code ran install, typecheck and tests afterwards: 11 passed, 2 failed |
| 2026-11-04 | Kiro CLI (`--v3`), fix session | Fixed both failures from the first `vitest` run. The network guard assigned to `import * as http` namespace objects, which are read-only at runtime, so it switched to the mutable default imports. Replay seeded its first message with a hard-coded string, so strict mode rejected step one; it now uses the recorded input. Also wrote `tests/gate/gate.test.ts` for the spec's gate | `tsc` passed while the code was broken: both bugs only showed up when the tests ran |
| 2026-11-04 | Kiro CLI (`--v3`), zero-network test rewrite | A mutation check (Claude Code commented out the `fetch` guard) showed the zero-network test still passed: it never called a guarded surface during replay. Kiro split the guard into `withNetworkGuard`, gave each of six surfaces its own failing case, and added a test that `replayTrace` runs under the guard. Re-checked: removing any one patch, or the guard itself, now fails a test | A passing property test can still test nothing. The mutation check found it, not the test run |
| 2026-11-04 | Kiro CLI, spec mode, started from Claude Code | Wrote spec 02 (fork and compare) from `kiro-prompts/02-fork-and-compare.md`, reading spec 01 and its code first | It built on spec 01's real API and named the schema changes. It also designed around a Recorder method that doesn't exist |
| 2026-11-04 | Kiro CLI, spec mode, review pass | Revised spec 02 against a nine-point review. An edited model call now runs live instead of keeping its old answer. The Recorder gets a real `continueFrom`. Compare aligns by position, so the original run is no longer empty. The first difference is reported for both sides, so swapping the branches gives the mirrored answer. Spend caps now count actual cost | The two worst findings were product logic, not code: a stale answer after an edit, and an empty compare for the most common case |
| 2026-11-04 | Kiro CLI, spec mode, third pass | Removed a blank placeholder step it had added for model call edits, and the last four em dashes it had said were gone | Check the claim, not the summary: its report said the em dashes were fixed when four remained |
| 2026-11-04 | Kiro CLI (`--v3`), spec 02 build, first session | Did Tasks 1 to 5: the schema change to 1.1.0 with `live` and `edited`, the migration, `Recorder.continueFrom`, and the fork and compare property tests, against stubs that throw "not implemented" | Splitting the session at the tests worked: Claude Code ran them and saw all three fail on "not implemented" before any fork or compare code existed. This was the first real red step of the build |
| 2026-11-04 | Kiro CLI (`--v3`), spec 02 build, second session | Wrote the spend caps, `forkTrace`, `compareBranches`, network guard scope tests and the gate test. 67 tests pass | The session hung at the end, retrying an edit to this log that its tools weren't allowed to make, and was stopped. Review found four gaps the tests missed: caps reset on every fork, spend counted the estimate, a cap hit dropped completed steps, and no test caught an edited prompt keeping its old answer |
| 2026-11-04 | Kiro CLI, fix session | Throttled on its first request: `CREDIT_CONSUMPTION_RATE_EXCEEDED`, retry after one hour. Made no changes | Watch the credit rate, not just the total |
| 2026-11-04 | Kiro Pro account | Switched the CLI from the personal account to the Kiro Pro account after the credit-rate throttle | The throttle was on the account. A new login cleared it at once |
| 2026-11-04 | Kiro CLI (`--v3`), fix sessions | Applied the four review fixes: a shared `SpendLedger`, charging actual cost, a Recorder `onStep` callback so a cap hit keeps completed steps, and the live output on an edited model call. Each has a test in `tests/compare/bug-fixes.test.ts` | Two sessions ended up running on the same files at once: a scheduled run didn't stop when cancelled, and was killed part way through a test edit. That left two tests failing. A later session couldn't apply its fix because in-place edits are refused under our tool trust list; it worked once told to write whole files. Mutation check after: breaking each fix fails 1 to 3 tests |
| 2026-11-04 | Kiro CLI (`--v3`), close-out | Ticked all of spec 02's tasks with Verified lines from the test runs | 78 tests, typecheck and build clean |
